# Синхронизация

## Хранилища и инициаторы

`budget-local` продолжает хранить локальный бюджет. В отдельной IndexedDB `budget-cloud-v1` находятся идентификаторы текущего профиля и бюджета, подтверждённая копия записей, курсор и неподтверждённая очередь. Приложение хранит одну активную облачную копию на профиль браузера. Идентификаторы помогают сверять область запроса с cookie, но не удостоверяют доступ.

Запросы выполняются при запуске, событии `online`, возвращении на экран, явном обновлении и после локальных изменений. Видимая вкладка опрашивает сервер раз в 20 секунд. При ошибке периодические запросы повторяются с возрастающей паузой до двух минут. Закрытая PWA отправляет очередь при следующем запуске.

## Запись и подтверждение

Интерфейс показывает изменение после записи очереди в Dexie. Запись получает случайный ID мутации и ожидаемую версию сущности. Повтор после потери связи использует прежние ID и тело. D1 проверяет сессию, версию и ссылочную целостность. Подтверждение сохраняется в одной транзакции с изменением. Повтор возвращает сохранённое подтверждение.

Клиент отправляет начало очереди в `POST /api/v1/sync/mutate`. Запись содержит `id`, `kind`, `key`, `expectedVersion` и `value`. Версия 0 означает отсутствие записи, а `value: null` означает удаление. Идемпотентность привязана к бюджету, участнику и ID мутации. Сервер сверяет хеш содержимого с сохранённым запросом. Чек и его позиции передаются одним документом, после чего клиент вычисляет операции. Для переноса лимита сервер проверяет текущий период и остатки категорий, а при записи сверяет ревизию состояния, использованного для расчёта.

Клиент читает изменения через `GET /api/v1/sync?after=<cursor>`. Ответ содержит `cursor`, `records`, `more` и при сбросе `reset`. Страница содержит до 100 записей, с дополнительным ограничением по оценочному объёму 1 МиБ. Одна запись может перескочить через несколько промежуточных версий, если успела измениться несколько раз. Маркеры удаления передаются как записи с `value: null`. Если курсор клиента выше текущего курсора D1, сервер начинает выдачу с начала и отмечает сброс. Клиент перестраивает подтверждённую копию и сохраняет локальную очередь.

Курсор меняется только после безопасного чтения всех страниц. Подтверждение отдельной записи не перескакивает через несвязанные изменения. Неизменившийся курсор не вынуждает перезагружать историю. Срок хранения отметок удаления и подтверждений в текущей версии не ограничен, чтобы старое устройство могло повторить неподтверждённую запись. Контролируйте объём D1 и сохраняйте резервные копии.

## Конфликты и доступ

При HTTP 409, 400 или 422 отправка очереди приостанавливается на ошибочной записи. Интерфейс сохраняет локальную правку и показывает серверное состояние, если оно есть в ответе. В зависимости от ошибки можно принять серверную запись, повторно отправить свою или ввести новую сумму операции. Связанные последующие правки тоже требуют просмотра, если опирались на конфликтующую локальную версию. Финансовые лимиты, имя бюджета и параметры недели составляют общую версию профиля.

При выборе повторной отправки конфликтующая правка получает новый ID и версию, основанную на текущей записи сервера. Дубликат фискального чека обрабатывается отдельно. Отклонённый документ остаётся доступен в очереди, но исключается из расчёта итогов. При принятии имеющегося чека также отбрасываются ожидающие правки к его отклонённому дубликату.

Восстановление финансового снимка использует `POST /api/v1/migrate`, отдельный ID и ожидаемый курсор всего бюджета. Изменение исходной ревизии останавливает перенос. Для новой попытки владелец сверяет обновившееся состояние и подтверждает перенос заново. [Перенос данных](data-migration.md)

При завершении сессии облачный экран закрывается до восстановления доступа. Очередь остаётся на устройстве. Выход очищает облачную копию. При наличии неподтверждённых данных пользователь сначала получает возможность сохранить копию и отдельно подтверждает удаление очереди. Локальный бюджет остаётся в своём хранилище. Второй участник может окончательно покинуть бюджет и освободить место для нового приглашения. Его финансовая история сохраняется у владельца.
