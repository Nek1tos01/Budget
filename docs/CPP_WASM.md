# Финансовое ядро C++20 и WebAssembly

Исходники находятся в `cpp/budget-core/`. CMake собирает нативную библиотеку и тесты. Emscripten собирает те же модули вместе с C ABI в `src/domain/budget-core.wasm`. Vite публикует модуль отдельным файлом с хешем содержимого. Service Worker кэширует его при установке PWA.

## Расчёты и граница с React

- `money.cpp` хранит копейки в `int64_t`, проверяет сложение и вычитание перед вычислением и округляет проценты целочисленно до ближайшего целого. При равных расстояниях результат округляется к большему целому.
- `calendar.cpp` принимает григорианские даты `YYYYMMDD` и возвращает начало периода включительно и конец периода исключительно. Финансовая неделя начинается в выбранный день с понедельника (1) по воскресенье (7). Месяц начинается первого числа. Поддерживаются сдвиги периода вперёд и назад.
- `engine.cpp` суммирует расходы и доходы по отдельности, вычисляет остаток и перерасход. Процент использования отсутствует при нулевом лимите. Для недельного, месячного и категорийного бюджета применяется лимит выбранного периода. Доходы учитываются в отдельном показателе. Аналитика группирует расходы по категории или плательщику, а сравнение периодов и точки тренда используют суммы из того же ядра. При совпадении сумм группы сохраняют порядок первого расхода в периоде.
- В недельных итогах, категориях и графиках используются расходы с недельным режимом учёта. Фактические платежи суммируются по датам независимо от режима и показываются отдельно, когда отличаются от бюджетных. Округление импортированного итога выполняется целочисленно через остаток от деления на 100 и проверяемое сложение.
- `src/domain/engine.ts` преобразует момент времени в местную дату бюджета через Temporal и IANA-идентификатор. Следующий сброс преобразуется из локального начала дня обратно в точный момент. Переходы часового пояса обрабатываются при преобразовании в обе стороны.
- `src/domain/budget-wasm.ts` асинхронно загружает модуль и вызывает `_initialize` автономной сборки Emscripten. Вызовы передают целые копейки как `BigInt` или поля `i64` в линейной памяти. Адаптер проверяет безопасность целого при чтении и записи старого JavaScript-формата `number`. Результаты процентов преобразуются для отображения. Буферы освобождаются в `finally`, в том числе при ошибках валидации.

Интерфейс загружается после инициализации ядра. Ошибка загрузки показывает кнопку повтора. При запуске без сети доступен ранее установленный кэш PWA.

## Прогноз

Прогноз для текущей недели или месяца использует средний расход за завершённые дни периода, включая дни без покупок. Для текущего и каждого будущего дня ядро берёт большую из двух сумм: средний расход или уже записанный расход за этот день. Итоговый прогноз округляется до копейки после суммирования. Доходы и расходы, которые по своему режиму не входят в выбранный период, исключаются из прогноза. Уверенность зависит от числа завершённых дней и дней с расходами.

## Сборка и тесты

Для нативной сборки нужны CMake 3.20+ и компилятор с поддержкой C++20, включая календарную часть `std::chrono`. Команды из корня проекта подходят и для генераторов с несколькими конфигурациями.

```sh
cmake -S cpp/budget-core -B build/budget-native
cmake --build build/budget-native --config Release
ctest --test-dir build/budget-native -C Release --output-on-failure
```

Для пересборки WebAssembly установите Emscripten SDK 4.0.20 в отдельный каталог. Команды ниже подходят для Linux, macOS и WSL. [Инструкция Emscripten](https://emscripten.org/docs/getting_started/downloads.html).

```sh
git clone --branch 4.0.20 --depth 1 https://github.com/emscripten-core/emsdk.git
cd emsdk
./emsdk install 4.0.20
./emsdk activate 4.0.20
source ./emsdk_env.sh
```

На Windows команды установки выполняются через `emsdk.bat`. Для активации переменных сборки запустите `emsdk_env.bat` в той же сессии `cmd.exe`. Запустите сборку и тесты из корня Budget.

```sh
npm run build:wasm
npm test
npm run build
npx playwright test tests/e2e/budget-wasm.spec.ts
```

При изменениях в C++ обновляйте в репозитории и `src/domain/budget-core.wasm`. Для обычной сборки и запуска React достаточно включённого файла. Vitest загружает этот файл с диска. Playwright проверяет MIME-тип и сигнатуру модуля по HTTP, восстановление после ошибки загрузки, расчёт через интерфейс и повторный запуск после выключения сети.
