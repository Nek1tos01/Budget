# Безопасность общего бюджета

## Доступ и восстановление

- При создании бюджета и принятии приглашения сервер создаёт индивидуальную сессию и один раз показывает отдельный код восстановления. Сохраните код в менеджере паролей. Восстановление завершает прежние сессии профиля и выдаёт новую сессию вместе с кодом на замену. Сохраните новый код и подтвердите замену в течение 15 минут. До подтверждения действует исходный код. Если владелец теряет все сессии и код, он может создать новый бюджет и восстановить финансовые данные из JSON-копии. Второму участнику владелец может выдать новое приглашение после отзыва недоступного профиля.
- Сессионный токен содержит 32 случайных байта. Cookie `budget_session` имеет `HttpOnly`, `SameSite=Strict`, `Path=/api/v1` и `Secure` по HTTPS. HTTP поддерживается только на loopback для разработки. Сессия действует 30 дней и продлевается при открытии приложения, когда остаётся менее 7 дней. Выход завершает текущую сессию.
- Одноразовое приглашение действует 15 минут. Новая ссылка заменяет предыдущую. Секрет передаётся во фрагменте URL и удаляется из адресной строки при обработке. Сервер получает его в теле JSON при присоединении.
- В D1 хранятся SHA-256-хеши случайных сессионных токенов, приглашений и кодов восстановления. Обработчики возвращают клиентские ошибки без внутренних сообщений D1. В приложении нет журналирования входящих тел запросов или заголовков `Cookie`.
- Частота создания бюджетов, присоединения и восстановления ограничена в D1 по часовым окнам для IP и для всей установки. Выдача приглашений ограничена по бюджету и для всей установки. `429` содержит `Retry-After`.

## Права и целостность

Сервер определяет пользователя по действующей сессии и активному профилю. Запросы синхронизации, восстановления данных, подтверждения кода, приглашения, отзыва доступа и выхода требуют совпадения `X-Budget-Household` и `X-Budget-Member` с сессией. Эти заголовки защищают от переключения cookie в другой вкладке. Для запросов `POST` необходимы совпадающий `Origin` и `application/json`. API не включает CORS для внешних сайтов.

Только владелец приглашает, отзывает доступ и восстанавливает облачные данные из копии. Оба участника могут редактировать общие финансы и собственное имя или цвет. Владелец и второй участник занимают разные роли, каждая роль допускает только один активный профиль. Отзыв доступа и добровольный выход второго участника из бюджета удаляют его сессии и коды восстановления. Исторический профиль остаётся в записях как плательщик или автор. Следующее приглашение создаёт отдельный профиль.

Ключ записи действует внутри конкретного бюджета. Проверка сессии, версии, ссылок и идентификатора мутации входит в транзакцию записи D1. При обычных изменениях сервер устанавливает автора и время создания операции, а редактирование их сохраняет. При восстановлении владелец может вернуть автора из копии, если автор соответствует профилю этого бюджета. В остальных импортированных записях автором становится владелец, выполнивший восстановление. Плательщик переносится отдельно.

При восстановлении доступа с неподтверждёнными правками приложение передаёт оба идентификатора локального профиля. D1 проверяет их до создания новой сессии. Если ответ с новым кодом потерялся или срок подтверждения истёк, восстановление можно повторить исходным кодом. Сервер принимает подтверждение только от последней сессии восстановления и возвращает то же подтверждение при повторной отправке. В базе оба кода хранятся в виде хешей.

Объектные схемы проверяют поля, даты, ссылки и суммы. Общие лимиты, лимиты категорий и суммы ручных операций передаются десятичными строками. Чеки и переносы лимитов используют целочисленные поля в копейках. D1 вычисляет общий оборот целочисленно и ограничивает его диапазоном точного хранения в текущем интерфейсе. Тела запросов мутации и переноса ограничены 1 МиБ, прочие POST-запросы — 32 КиБ. Копия применима только к ожидаемой ревизии, а повтор того же запроса возвращает первое подтверждение.

## Хранение и кэш

API возвращает `Cache-Control: private, no-store` и `Cross-Origin-Resource-Policy: same-origin`. PWA кэширует статику и WebAssembly. Офлайн-данные и ожидающие изменения хранятся в IndexedDB по профилям. На общем устройстве закрывайте сессию после синхронизации. При отзыве доступа сервер прекращает выдачу данных, а уже сохранённые файлы и доступ к открытой офлайн-копии зависят от устройства.

Для статических ресурсов Pages задаёт CSP через [`public/_headers`](../public/_headers). Политика ограничивает подключения и worker-скрипты текущим источником, запрещает встраивание приложения во фреймы и разрешает WebAssembly. Камера доступна текущему источнику, микрофон и геолокация отключены. QR и OCR работают в браузере. При отправке чека в общий бюджет передаётся сохранённый документ с распознанными и подтверждёнными данными. Фото обрабатывает локальный worker. [Распознавание чеков](receipt-ocr.md)

D1 хранит последнюю версию записи и маркеры удаления, чтобы давно отключённое устройство получило актуальное состояние. Подтверждения мутаций сохраняются для повторных запросов и могут содержать данные уже удалённой записи. Резервные копии D1 также могут содержать прежнее состояние базы.

В JSON-копии содержатся личные финансовые данные. Храните её отдельно от кода восстановления и передавайте только участникам бюджета.
